## omafish 4.0.5

Profiles now bring your AI conversations back along with your windows, and they work in herdr as well as tmux.

### New

- **`tdp` resumes your AI conversations.** `tdp save` records the coding agents running in each window, and `tdp <name>` resumes them when it reopens the windows. Claude comes back to the exact conversation. Codex and opencode continue their latest conversation in that folder.

  ![tdp save listing each window with its agents](https://github.com/crmne/omafish/releases/download/4.0.5/tdp-agents.png)

- **`hdp`: the same profiles in herdr.** `hdp save`, `hdp <name>`, `hdp ls`, `hdp edit`, and `hdp rm` work like their `tdp` versions, with herdr tabs as `hdl` layouts. Both commands share `~/.config/tdp/`, so a profile saved in tmux opens in herdr and the other way round. From outside herdr, `hdp` starts a server if none is running and attaches once the tabs are ready.
- **`tdp save <name> --all`** saves every window without the picker or the overwrite question, so you can run it from a timer and always have a recent profile.

### Upgrading

- Existing profiles keep working: a line with only a folder opens with `cx`, as before.
- `tdp <name> <ai>` still starts every window fresh with the AI you name, ignoring saved conversations.

### Known limitations

- Codex and opencode don't report which conversation a running process belongs to, so two codex (or two opencode) panes in the same folder both reopen the latest one.
- A claude nobody has typed in yet has no conversation to resume, so it reopens fresh.
- Resuming has been tested with stand-in agents, not by reopening real conversations.
- herdr can also restore a whole session after a restart on its own, once its agent integrations are installed (`herdr integration install claude`, and so on). `hdp` is for opening a chosen set of projects, or a profile saved in tmux.
